# tools: agent rules

Go commands, run from the repository root. Most write a bundle for a Windows guest that a separate runner
executes; nothing here runs on Windows.

| command | writes | contract |
|---|---|---|
| `go run ./tools/vmbundle -o DIR` | DLL load-and-type test: both `yakbd-wincheck` builds, the corpus, expectations | `ARCHITECTURE.md` "The Windows test runner" |
| `go run ./tools/instbundle -o DIR` (`-guest w11x64\|w10x64\|w10x86\|w11signin\|w11signin2\|w11signin3`, `-arm64`) | installer test, checker `tools/instcheck` | `docs/installer.md` §8 (§8.3: `w11signin`, `w11signin2`, `w11signin3` with the host driver `drive.ps1`) |
| `go run ./tools/clibundle -o DIR` | command-line test, checker `tools/clicheck` | `docs/installer-cli.md` |
| `go run ./tools/importbundle -o DIR` | DLL import check | `docs/dll-import.md` §5 |
| `go run ./tools/msklcbundle -o DIR` | MSKLC comparison, guest driver `tools/msklcbundle/guest` | `docs/dll-import.md` §6 |
| `go run ./tools/instbundle -guest w11plant -o DIR` | DLL planting check: marker DLL planted next to the installers in Downloads, autonomous `drive.ps1` | `docs/installer.md` §5.2, §8.4 |
| `go run ./tools/instbundle -guest w11suite -assets DIR -old DIR -o OUT` | the two YAKBD installers: the release's clean checks, a silent state-table subset with the takeover of the published earlier installers, the wizard in eight states with screenshots | `docs/installer-cli.md` §12.7 |
| `go run ./tools/cldrbundle -o DIR` | CLDR conformance: every CLDR test case a Windows build can express, typed by both `yakbd-wincheck` runners | `docs/cldr.md` §4 |

`tools/macos-check` is not Go: a Swift checker and a shell driver for GitHub's Mac runners (workflow `macos-layout-check.yml`, contract `tools/macos-check/README.md`); a case may be a `layout.kbl.json` that the driver builds with yakbd (`compile -target macos -emit-expectations`).

`tools/xkb-check` is not Go either: C helpers built inside Docker images and a shell driver, `tools/xkb-check/run.sh OUTDIR`, that types test layouts through X11, sway, weston, KWin and mutter in rootless Docker (contract `tools/xkb-check/README.md`). Run it once per relevant change, not in loops.

`tools/buildstub` and `tools/toolsetup` belong to `installer/AGENTS.md`; `tools/release` (every release asset, reproducible) to `docs/release.md`; `tools/genucd` to
`internal/unicode/norm/AGENTS.md`.

- Write bundles outside the repository (`/vmbundle/` is ignored for a stray one).
- Each bundle's README with the guest commands is generated by its Go code (for example
  `tools/msklcbundle/readme.go`, `readme()` in `tools/vmbundle/main.go`); change the generator, not a written copy.
- A guest program that calls the Windows API keeps that code in `*_windows.go` with a `main_other.go` stand-in
  (`tools/instcheck`, `tools/clicheck`), so `go vet ./...` and `go test ./...` pass on Linux.
- A bundle holds only our own files. MSKLC is never part of one, and nothing MSKLC produces leaves the guest except
  the text the guest driver writes.
- When the runner reports back, record the run (date, guest, commit, pass counts) in the contract document.
